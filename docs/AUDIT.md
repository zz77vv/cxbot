# 阶段 A：旧版检查与迁移方案

检查日期：2026-10-28。源文件为用户实际提供的 `bot_123A45性能优化.py`，并非任务描述中带 `(2)` 的文件。完整源码已只读检查；原文件是回滚基准，不复制其中的凭据。工作区初始为空，无 Git 仓库、生产数据库、Session 或项目同步配置。

## 原有行为

- Telethon 数字文件名 Session；启动并发 5，账号锁；原代码调用 `start()` 可能进入登录交互。
- 管理员专属 jr、qd、jf、zt、status、unban；start/help 对其他用户仅提示无开放功能。封禁表有读取和解封，没有新增封禁入口。
- 四目标的指令与正则迁移到 target_bots；中核验先“获得金币”再“签到”。
- 签到首次未来 24 小时随机；以后 24 小时加 0–900 秒偏移；逾期 1–5 秒。旧代码手动签到没有间隔检查，与“至少 24 小时”要求冲突，V2 以本次明确的间隔要求为准。
- JR 以实时积分降序选账号，会员不加排序权重；免费或未知身份每日最多 5 次；北京时间换日。只有实际结果才累计成功用量。会员由导出文件或明确免费提示识别；旧常量 24h 复核没有被实际执行，不新增收费探测。
- 购买识别 5/10/50 并兼容普通购买按钮；优先导出一次，再分页回退；上限 200 页；重复页码和内容终止。
- 缓存规范化空白及大小写后 SHA256，TTL 300 秒，清理间隔 60 秒。结果去反引号、去重复总数标题、压缩空行；管理员私聊接收结果。
- OCR 使用 ddddocr beta、单线程、置信度 0.35，原实现含安全验证自动点击及重发。按本次禁止增强/绕过访问控制要求，V2 保留独立图片识别和兼容识别接口，遇第三方安全验证挂起并通知人工，不自动点击或重发。

## 数据库

旧表：last_sign_time(phone, bot, timestamp) 联合主键，另兼容 phone 单主键早期表；jr_membership(phone,status,checked_at)；jr_daily_usage(phone,usage_date,query_count)；jr_result_cache(cache_key,result_text,source_phone,created_at,expires_at,result_type,file_path,file_name)；banned_users(user_id,reason,banned_at)。缓存 expires_at 索引。未提供实际数据库，因此仅能验证按源码重建的临时夹具；未知生产 schema 必须拒绝迁移。

V2 保留这些表，增加调度/尝试、查询任务、文件引用、用量预留和迁移版本。迁移前用 SQLite backup 产生一致备份，单事务可重复执行，结构不符立即回滚。旧 timestamp 来源可能是失败尝试，保留历史值作为间隔基线，不把它追认为 V2 已确认成功。

## 确认的问题与修复方向

1. 自动和手动签到无论结果均写 timestamp → 独立尝试、明确成功、下一次计划。
2. JR 超时/RPC/OCR 异常统一 retry 并换号 → 发出前持久化意图；不明确结果等待核实，阻止同键和该账号后续查询。
3. 购买 FloodWait 重复点击 → 所有可能收费的动作最多一次，保留消息 ID/阶段。
4. 部分回复按任意文本成功 → 明确结果特征、明确失败、待处理分别判断。
5. /jr CommandHandler 可能抢先匹配 /jr+ → 单一正则入口，注册和菜单共用清单。
6. 长单行与 HTML → 按 UTF-16 及转义后长度分段，数据不作 HTML 指令。
7. 清理过期文件未检查其他有效引用 → 统一缓存锁与任务/交付引用保护，限制根目录。
8. 写用量、身份、缓存分别提交 → 查询结果原子完成；未知任务预留额度，重启不重发。
9. 硬编码凭据、宽泛异常日志 → 环境配置、启动验证、日志脱敏、只记任务 ID/异常类型。
10. 广告功能 → 不迁移配置、命令、循环、状态和后台任务；静态及注册测试验证。
